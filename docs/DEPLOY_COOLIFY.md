# Deploying the backend on Coolify

The backend runs as one **Docker Compose** resource in Coolify v4, built from
this repository (`awjinnovation/sohar_portal`, branch `main`). Files:

| File | Role |
|---|---|
| `Dockerfile` | `serversideup/php:8.3-fpm-nginx-trixie-v5.0.3` (PHP-FPM + NGINX, non-root `www-data`, port 8080) + intl, bcmath, exif, gd, imagick. Targets `production` (deployed) and `test` (PHPUnit only). |
| `docker-compose.yml` | Services `app`, `worker`, `scheduler`, `mysql` (8.4.13), `redis` (7.4.11). Written for Coolify's magic variables. |
| `docker/nginx/*` | CORS on `/storage/*`, `/tenants/*`, `/images/*` for the web builds (production equivalent of `server.php`). |
| `.env.production.example` | Every variable the app reads, grouped, with the secrets marked `SET_IN_COOLIFY`. |

```
            Coolify proxy (Traefik/Caddy, TLS)  https://mawsim.awj.om
                              │ :8080
   ┌──────────────────────────┴──────────────────────────┐
   │ app        NGINX + PHP-FPM, /up health check         │  migrations + caches on every deploy
   │ worker     php artisan queue:work redis               │  SMS jobs
   │ scheduler  php artisan schedule:work                  │  expiries, pruning (routes/console.php)
   │ mysql      MySQL 8.4, utf8mb4        volume mysql-data, mysql-backups
   │ redis      cache, sessions, queue    volume redis-data (append-only)
   └──────────── volume app-storage = storage/app (uploads), shared by app/worker/scheduler
```

The gate web app (Flutter web build of the gate scanner) is **not** part of
this resource; see [Gate web app](#13-gate-web-app-separate-resource).

---

## 1. DNS

At the DNS host of `awj.om` (TTL 300 while setting up):

| Name | Type | Value |
|---|---|---|
| `mawsim.awj.om` | `A` | public IPv4 of the Coolify server |
| `mawsim.awj.om` | `AAAA` | public IPv6 (only if the server has one) |
| `gate.mawsim.awj.om` | `A` / `AAAA` | same server (gate web app, separate resource) |
| `app.mawsim.awj.om` | `A` / `AAAA` | same server (visitor web app, separate resource) |
| `awj.om` (optional) | `CAA` | `0 issue "letsencrypt.org"` |

Mail records (SPF, DKIM, DMARC) are in [§8](#8-smtp-spf-dkim-dmarc). Coolify
gets the Let's Encrypt certificates once the `A` records resolve.

## 2. Create the resource

1. Coolify → *Projects* → your project / environment → **+ New** → **Docker Compose** (from a Git repository).
   Use the **GitHub App** source for `awjinnovation/sohar_portal` (private repository).
2. Branch **`main`**, Base Directory **`/`**, Docker Compose Location **`/docker-compose.yml`**, build pack **Docker Compose**.
3. **Load** the compose file. Coolify lists the services and creates the environment variables declared in it.
4. Leave *Raw (deploy as-is)* off: Coolify adds its proxy labels, networks and the `.env` file.

## 3. Domains

*Configuration → General → Domains*, service **app**:

```
https://mawsim.awj.om:8080
```

`:8080` is the container port (not public); visitors use 443. Nothing else
gets a domain (worker, scheduler, mysql and redis stay on the private
network; there are no host `ports`). `APP_URL` follows this domain
(`APP_URL: ${SERVICE_URL_APP}` in the compose file), so do not set it by hand.
Use the final domain before the first real use: payment links, QR codes, the
gate pairing deep link and the landing page's link previews are built from it.

## 4. Environment variables

*Environment Variables* tab. Coolify fills the generated ones on the first
load and keeps them; `${VAR:?}` variables block the deploy until set.

**Required before the first deploy**

| Variable | Value |
|---|---|
| `APP_KEY` | `base64:…`, see [§5](#5-generate-app_key). |

**Generated by Coolify (do not change after the first deploy)**

| Variable | Used for |
|---|---|
| `SERVICE_URL_APP` / `SERVICE_FQDN_APP` | from the domain → `APP_URL` |
| `SERVICE_USER_MYSQL`, `SERVICE_PASSWORD_MYSQL` | `DB_USERNAME` / `DB_PASSWORD` and the MySQL user |
| `SERVICE_PASSWORD_MYSQLROOT` | MySQL root (backups, maintenance) |
| `SERVICE_PASSWORD_REDIS` | Redis `requirepass` / `REDIS_PASSWORD` |

Changing a generated database password later does not change it inside the
existing MySQL volume.

**Required before go-live**

| Variable | Notes |
|---|---|
| `MAIL_HOST`, `MAIL_PORT`, `MAIL_SCHEME`, `MAIL_USERNAME`, `MAIL_PASSWORD` | SMTP, [§8](#8-smtp-spf-dkim-dmarc). Defaults: `smtps`, 465, from `no-reply@awj.om`, demo requests to `systems@awj.om`. |
| `ISMARTSMS_USER_ID`, `ISMARTSMS_PASSWORD` | Without them no OTP SMS is sent, so nobody can sign in to the app. |
| `BANK_MUSCAT_GATEWAY_URL`, `BANK_MUSCAT_MERCHANT_ID`, `BANK_MUSCAT_ACCESS_CODE`, `BANK_MUSCAT_WORKING_KEY` | Platform fallback; a tenant can instead have its own (encrypted) in *Admin → Tenants*. The default URL is the UAT gateway. |
| `BANK_MUSCAT_WEBHOOK_IPS` | Comma-separated IPs of Bank Muscat's callback servers. |
| `CORS_ALLOWED_ORIGINS` | The web apps, comma-separated: `https://gate.mawsim.awj.om,https://app.mawsim.awj.om`. Default `*`. |

**Optional**: `OPENAI_API_KEY` (empty = AI features off), `OPENAI_MODEL_FAST/SMART`,
`AI_CHAT_RATE_*`, `PAY_LINK_BASE_URL`, `DEMO_REQUEST_CC`, `LOG_LEVEL` (`info`),
`TRUSTED_PROXIES` (add Cloudflare's ranges if its proxy is in front),
`TENANCY_DEFAULT_TENANT` (`north-batinah`), `PHP_MEMORY_LIMIT`. The full list with
comments is `.env.production.example`. Monthly AI token budgets are tenant
settings (*Admin → Branding & settings → AI assistant*), not variables.

Already fixed by the compose file: `APP_ENV=production`, `APP_DEBUG=false`,
`DB_CONNECTION=mysql`, `CACHE_STORE` / `SESSION_DRIVER` / `QUEUE_CONNECTION=redis`,
`PAYMENT_DRIVER=bankmuscat`, `LOG_CHANNEL=stderr`, `SESSION_SECURE_COOKIE=true`.
**Never** add `OTP_DEBUG` or `OTP_TEST_CODE` (ignored in production anyway)
and never set `PAYMENT_DRIVER=fake` on a public server.

## 5. Generate APP_KEY

Once, on any machine with Docker or PHP:

```bash
echo "base64:$(openssl rand -base64 32)"
# or, in a checkout of this repository: php artisan key:generate --show
```

Paste it into `APP_KEY` and store it in the password manager. It encrypts the
tenants' gateway credentials and signs OTP hashes, payment links and the
offline gate manifests: losing or changing it breaks those. To rotate, move the
old key to `APP_PREVIOUS_KEYS` and set a new `APP_KEY`.

## 6. First deploy

Press **Deploy**. Coolify builds the image (≈ 5 min the first time; later
deploys reuse the cached layers) and starts:

1. `mysql` and `redis` until healthy;
2. `app`: waits for MySQL, runs `php artisan migrate --force` (with `--isolated`
   from the second deploy on, using a Redis lock), then `php artisan optimize`
   (config, routes, views, events), then NGINX + PHP-FPM. It is healthy when
   `GET /up` answers 200, and only then does Coolify's proxy route traffic to it;
3. `worker` and `scheduler` once `app` is healthy (they never migrate).

A Compose deployment replaces the containers in place, so expect a short gap
(the new `app` migrates and warms its caches before it is healthy). If a
migration fails, `app` exits and never turns healthy, and worker / scheduler do
not start: read the `app` log, fix, deploy again (or roll back, [§12](#12-scaling-updates-rollback)).
Check afterwards:

```bash
curl -fsS https://mawsim.awj.om/up
curl -fsS -H 'X-Tenant: north-batinah' https://mawsim.awj.om/api/v1/tenant/config | head -c 300
```

## 7. Seed once, then create the real super-admin

Seeding **never** runs automatically. In Coolify open the **app** service →
*Terminal* (or SSH to the server: `docker exec -it app-<uuid> sh`):

```bash
php artisan db:seed --force
```

It creates the roles, the `north-batinah` and `demo` tenants, their events,
ticket types, places, gates and the seeded staff accounts. It is idempotent: it
can be re-run (it only adds what is missing and never overwrites admin edits).

The seeded accounts all use the password `password123` (README). Create your
own platform super-admin and lock the seeded ones in the same step:

```bash
php artisan platform:create-admin ops@awj.om --name="AWJ Ops"                 # prompts twice (min 12 characters)
php artisan platform:create-admin ops@awj.om --generate --lock-seeded          # prints a random 24-character password once
```

`--lock-seeded` gives every e-mail account that still has the seeded password a
random one nobody knows (set real ones later in *Admin → Users*). Then sign in
at `https://mawsim.awj.om/admin/login`, review the tenants, and switch off or
re-price the **sample** ticket types before sales open (README → *Seeded prices*).
To start without the sample content instead, seed only the roles
(`php artisan db:seed --class=RolesAndPermissionsSeeder --force`): the migrations
already create a bare `north-batinah` tenant, the super-admin can sign in to it
and add tenants in *Admin → Tenants*.

## 8. SMTP, SPF, DKIM, DMARC

Use a transactional provider (Google Workspace / Microsoft 365 SMTP, Amazon SES,
Mailgun, Postmark, Brevo, …) that can send as `no-reply@awj.om`:

```dotenv
MAIL_MAILER=smtp
MAIL_SCHEME=smtps        # implicit TLS on 465; for STARTTLS on 587 leave MAIL_SCHEME empty
MAIL_HOST=smtp.provider.example
MAIL_PORT=465
MAIL_USERNAME=no-reply@awj.om
MAIL_PASSWORD=…          # app password / SMTP key
MAIL_FROM_ADDRESS=no-reply@awj.om
DEMO_REQUEST_TO=systems@awj.om
```

DNS on `awj.om` (values come from the provider):

| Record | Example |
|---|---|
| SPF | `awj.om TXT "v=spf1 include:<provider's SPF host> ~all"`: **one** SPF record per domain; merge includes if one exists. |
| DKIM | the CNAME/TXT records the provider gives (e.g. `selector._domainkey.awj.om`). |
| DMARC | `_dmarc.awj.om TXT "v=DMARC1; p=quarantine; rua=mailto:dmarc@awj.om"` (start with `p=none` to observe). |

Test: submit the *Book a demo* form on `https://mawsim.awj.om/#demo`; the row
appears in *Admin → Platform → Demo requests* with *mailed*; failures are logged
(the submission still succeeds). Many hosts block outbound port 25; 465/587 work.

## 9. Bank Muscat

Send Bank Muscat (CCAvenue non-seamless) these URLs for the merchant profile /
whitelist:

| Purpose | URL |
|---|---|
| Redirect (return) URL | `https://mawsim.awj.om/payment/success` (sent per transaction with `?transaction_id=…`) |
| Cancel URL | `https://mawsim.awj.om/payment/cancel` |
| Server-to-server webhook | `https://mawsim.awj.om/api/v1/payments/webhook` (POST) |
| Website / registered domain | `https://mawsim.awj.om` (and the server's public IP if they ask for the requesting IP) |

Ask them for the IPs their callbacks come from and put them in
`BANK_MUSCAT_WEBHOOK_IPS`. Switch `BANK_MUSCAT_GATEWAY_URL` from the UAT URL to the
production one they give you. Responses are only accepted after decryption with
the tenant's working key and an exact order / currency / amount match.

## 10. Backups

What to keep: the **MySQL database**, the **`app-storage` volume** (uploaded
images, tenant logos), and **`APP_KEY`** (password manager). Redis only holds
cache, sessions and pending jobs.

**MySQL** — Coolify → the resource → *Scheduled Tasks* → *Add*:

- Name `mysql-backup`, Container **`mysql`**, Frequency `0 1 * * *` (daily 01:00 UTC);
- Command:

```sh
sh -c 'MYSQL_PWD="$MYSQL_ROOT_PASSWORD" mysqldump -uroot --single-transaction --routines --triggers --no-tablespaces --set-gtid-purged=OFF --databases "$MYSQL_DATABASE" | gzip > /backups/mawsim-$(date +%F-%H%M).sql.gz && find /backups -name "*.sql.gz" -mtime +14 -delete'
```

Dumps land in the `mysql-backups` volume (14 days kept). Copy them off the
server, e.g. a host cron with `rclone` / `restic` / `aws s3 sync` from the volume
path (`docker volume inspect <uuid>_mysql-backups --format '{{.Mountpoint}}'`), or to S3-compatible storage.
(Coolify's built-in S3 database backups only cover standalone database
resources, not databases inside a Compose resource.)

**Uploads** — on the server (host cron, after the dump):

```bash
# containers are named <service>-<resource uuid>, volumes <resource uuid>_<volume>
docker exec app-<uuid> tar czf - -C /var/www/html/storage/app . > /root/backups/mawsim-storage-$(date +%F).tgz
```

**Restore** (stop `worker` and `scheduler` first):

```bash
gunzip -c mawsim-2026-12-01-0100.sql.gz | docker exec -i mysql-<uuid> sh -c 'MYSQL_PWD="$MYSQL_ROOT_PASSWORD" mysql -uroot'
docker exec -i app-<uuid> tar xzf - -C /var/www/html/storage/app < mawsim-storage-2026-12-01.tgz
```

Test a restore on a staging resource once before the season.

## 11. Logs and monitoring

- Coolify → the resource → **Logs**, per container. Laravel logs to stderr
  (`LOG_CHANNEL=stderr`, `LOG_LEVEL=info`; set `debug` temporarily if needed),
  NGINX access logs to stdout (client IP in the last field, from `X-Forwarded-For`).
- `app`: requests, PHP errors, migrations at start. `worker`: one line per job
  (`App\Jobs\SendOtpSms … DONE/FAIL`), SMS gateway errors. `scheduler`: one line per
  scheduled command (`box-office:expire` every minute, `payments:expire-pending`
  hourly, `points:expire` 02:00, `wallet:expire-promo` 02:15, `ai:prune` 03:10 UTC).
- Failed jobs (after 3 tries) are kept in MySQL: `php artisan queue:failed`,
  `php artisan queue:retry all`, `php artisan queue:flush`.
- Health: Coolify shows each service's Docker health (app `/up`, worker / scheduler
  process checks, MySQL query, Redis ping). Add an external uptime check on
  `https://mawsim.awj.om/up`.

## 12. Scaling, updates, rollback

**Worker.** Coolify gives every service a fixed container name, so
`deploy.replicas` / `scale` are rejected. Add instances as services, one line
each in `docker-compose.yml` (all share the definition `x-worker`):

```yaml
services:
  worker: *worker
  worker-2: *worker
```

Redeploy. Jobs are spread over the workers by Redis. The scheduler must stay a
**single** instance. The `app` service can be given more PHP-FPM children with
`PHP_FPM_PM_MAX_CHILDREN` (default 20) and a larger server.

**Updates.** Push to `main` and press *Deploy* (or enable the GitHub
auto-deploy webhook). Each deploy rebuilds the image, runs new migrations once
in `app`, then replaces worker and scheduler (`queue:work` finishes its current
job on SIGTERM). Bump the base image deliberately by editing `PHP_IMAGE` in the
`Dockerfile` (watch https://github.com/serversideup/docker-php/releases for PHP
security releases).

**Rollback.** Coolify tags each build with its commit, so *Deployments* →
pick an earlier successful deployment → **Rollback** redeploys that image.
Migrations are **not** reversed: keep migrations backward compatible (add
columns / widen, never drop in the same release that stops using them). If a
release changed data irreversibly, restore the database from the last dump
([§10](#10-backups)) instead.

## 13. Gate and visitor web apps (separate resources)

The gate scanner's web build (`lib/gate/**` in the Flutter app repository
`../sohar_north_app`) is deployed as **its own Coolify resource from that
repository**, not from this one, on `https://gate.mawsim.awj.om`. Point it at
`https://mawsim.awj.om` as its API base and the tenant slug, and add its origin
to this resource's `CORS_ALLOWED_ORIGINS` (it calls `/api/v1/gate/*` and loads
`/tenants/*` and `/storage/*` images). Devices pair from *Admin → Gates →
Scanner devices → Pair new device* (the QR carries `api=https://mawsim.awj.om`).

The visitor app's web build (events, tickets, wallet, map in the browser) uses
the same Dockerfile from the same repository as a second resource, with the
build variables `APP=visitor` and `PUBLIC_URL=https://app.mawsim.awj.om`, on
`https://app.mawsim.awj.om`. Add that origin to `CORS_ALLOWED_ORIGINS` as well.
Steps: `deploy/gate-web/README.md` → "Visitor web app" in the app repository.

## 14. Test the stack locally

Same compose file, plus a small override with a host port and test-only values
(never commit those values):

```yaml
# docker-compose.local.yml (not committed)
services:
  app:
    ports: ["127.0.0.1:18080:8080"]
    environment:
      OTP_TEST_CODE: "123456"
```

```dotenv
# local.env: what Coolify would generate
APP_KEY=base64:…
SERVICE_URL_APP=http://localhost:18080
SERVICE_USER_MYSQL=mawsim
SERVICE_PASSWORD_MYSQL=…
SERVICE_PASSWORD_MYSQLROOT=…
SERVICE_PASSWORD_REDIS=…
SESSION_SECURE_COOKIE=false
MAIL_MAILER=log
APP_ENV=staging          # the fake gateway and OTP_TEST_CODE are refused in production
PAYMENT_DRIVER=fake
```

```bash
docker compose -p mawsim-local --env-file local.env -f docker-compose.yml -f docker-compose.local.yml up -d --build
docker compose -p mawsim-local exec app php artisan db:seed --force
# PHPUnit against MySQL (separate database mawsim_testing, created as root first):
docker build --target test -t mawsim-backend:test .
docker run --rm --network mawsim-local_default -e APP_KEY=… -e DB_CONNECTION=mysql -e DB_HOST=mysql \
  -e DB_DATABASE=mawsim_testing -e DB_USERNAME=… -e DB_PASSWORD=… mawsim-backend:test php artisan test
docker compose -p mawsim-local down -v      # removes the containers and the volumes
```
